# 动作切点检测工具（action-cut detector）

把"人眼逐帧看视频、标出动作起止"这件事自动化。

这类岗位对人眼消耗极大，我认为这种活不该由人来做。

## 这是什么

输入一段**固定机位**的视频（比如机械臂作业、装配工位），程序逐帧计算"运动量"，
自动找出每一段"开始动 → 停下"的时间点，输出：

1. 一个 CSV：每条记录 `start_frame` / `end_frame` / `duration_sec` / `confidence`
2. 一张运动量曲线图：把检测到的动作切点用色块和竖线标在曲线上

注意：这是**第一版 MVP**，只做"有没有动"，不做"做的是什么动作"。

## 怎么跑

```bash
# 1. 装依赖（Python 3.12+，Windows 直接可用）
pip install -r requirements.txt

# 2. 跑你的视频
python main.py 你的视频.mp4
```

默认会在当前目录生成：
- `actions.csv` —— 切点列表
- `motion_curve.png` —— 运动量曲线图

### 可调参数

切点的好坏取决于参数，参数都集中在 `detector.py` 文件顶部，改完重新跑即可：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `MOTION_THRESHOLD` | `None`（自动估计） | 运动量阈值，超过即认为"在动"；`None` 时按曲线分布自动估计 |
| `SMOOTH_WINDOW` | 5 | 平滑窗口（帧），越大曲线越光滑但也越迟钝 |
| `MIN_ACTION_FRAMES` | 15 | 最小动作时长（帧），短于这个算噪声 |
| `MIN_GAP_FRAMES` | 5 | 相邻动作最小间隔（帧），小于则合并 |
| `BASELINE_PERCENTILE` | 20 | 自动估计时，"静止基线"取的分位数 |
| `THRESHOLD_MARGIN` | 2.0 | 自动估计时的倍数（阈值 = 基线 × 该值，越小越灵敏） |

**默认阈值是自动估计的**：程序取运动量曲线的低分位（20%）当"静止基线"，阈值
就是基线的 2 倍。这样对任意亮度、分辨率、噪声水平的视频都能给一个合理起点，
**一条命令就能跑通，不用先看量级**。

**调参建议**：跑一遍看曲线图，如果漏检（动作段没被框出来），把
`THRESHOLD_MARGIN` 调小（更灵敏）或用 `--threshold` 显式给一个更低的阈值；
如果误报（噪声被框成动作），调大 `MIN_ACTION_FRAMES` 或 `--threshold` 调高。
切点被切得稀碎就调大 `MIN_GAP_FRAMES`。

### 用测试视频自检

仓库自带一段合成测试视频（有明确 ground truth），可以直接验证工具是否正常：

```bash
python make_test_video.py        # 生成 test_video.mp4（含 4 段已知动作）
python main.py test_video.mp4    # 应该检出 4 个切点
```

测试视频的 ground truth（机械臂"在动"的真实时间段）：

| 段 | 帧号 | 时间 |
|----|------|------|
| 1 | 30 ~ 90 | 1.0 ~ 3.0 秒 |
| 2 | 150 ~ 210 | 5.0 ~ 7.0 秒 |
| 3 | 270 ~ 330 | 9.0 ~ 11.0 秒 |
| 4 | 390 ~ 450 | 13.0 ~ 15.0 秒 |

正常情况下，`main.py` 检出的切点应该和上表一一对应，帧号误差在平滑窗口量级
（±3 帧左右），见 `motion_curve.png`。

## 原理

一句话：**相邻帧画面差异越大，说明动得越厉害。**

1. 逐帧读视频，转灰度图；
2. 当前帧和上一帧做 `absdiff`，取平均像素差 → 得到一帧的"运动量"；
3. 对整条运动量序列做滑动平均，压掉传感器噪声；
4. 找出所有"超过阈值"的连续区间，过滤掉过短的、合并掉贴太近的；
5. 每个区间就是一个动作切点。

具体每一行为什么这么写，见 `detector.py` 里的中文注释。

## 局限（第一版明确不做 / 做不到的）

- **不懂语义**：只能判断"有没有动"，不判断"抓没抓到""拧没拧紧"，更分不清
  动作类型。要做语义，需要上检测/跟踪/时序模型，那是另一个量级的事。
- **对背景变化敏感**：帧差法假设背景基本静止。如果机位在晃、有强光变化、
  画面里有别人走过，都会产生假动作。
- **阈值是经验值**：不同视频的亮度、分辨率、噪声水平不同，阈值需要人工
  对着曲线图调，做不到全自动"开箱即用"。
- **多目标不区分**：画面里同时动多个东西时，运动会叠加，无法单独切分每个。
- **不含跟踪、不含 GUI、不含批量**：这些留给后续版本。

## 文件结构

```
main.py             # 入口：读视频 → 检测 → 输出 CSV + 曲线图
detector.py         # 核心算法：帧差、平滑、切点检测（参数集中在顶部）
make_test_video.py  # 生成合成测试视频（含 ground truth）
requirements.txt    # 依赖
```

## 技术约束

- Python 3.12+（开发时用 3.13 验证过，向下兼容 3.12）
- opencv-python **5.x**（注意：不是网上大多数教程里的 4.x，API 有差异）
- numpy、matplotlib
- 纯 CPU，无 GPU 依赖，Windows 直接可跑
